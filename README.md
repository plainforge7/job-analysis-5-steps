# 🍎 岗位分析五步法 · Job Analysis 5 Steps

> 🧭 用五步法把岗位说明 📄、访谈记录 🎙️ 或业务需求 📊，整理为清晰的岗位画像 🖼️、能力要求 💪 和可衡量的绩效结果 📈。

![License](https://img.shields.io/badge/license-MIT-blue.svg) ![Skill](https://img.shields.io/badge/type-SKILL-green.svg)

## ✨ 它能做什么

- 🎯 **定义岗位目的** —— 一句话说清岗位为何存在 🤔、服务谁 🤝、解决什么业务问题 💼
- 🧩 **拆解关键职责** —— 把琐碎事项合并为 4–8 个职责领域 🗂️，按重要性排序 🔢，并标出依赖关系 🔗
- 🧠 **提炼任职能力** —— 覆盖知识/技能 📚、通用能力 🛠️、经验背景 🏆、行为特征 🎭 四类，每项都附带可观察证据 🔍
- 📏 **建立绩效指标** —— 口径 📐、周期 🗓️、数据源 🗄️ 齐全；没有基线就老实写「待基线确认」🙅，绝不编数字
- ✅ **岗位画像与校验** —— 做一致性体检 🩺：能力要服务于职责，指标要反映岗位目的，权限要撑得起责任 ⚖️

## 🛠️ 适用场景

| 场景 | 说明 |
| ---- | ---- |
| 🧲 招聘 | 生成真实不注水的 JD 📄 与面试判断标准 ✅ |
| 🏗️ 定岗 | 厘清汇报线 📠、决策权限 🔑 与职责边界 🚧 |
| 🗂️ 人才盘点 | 用同一套画像横向比较同岗人员 👥 |
| 🔧 岗位优化 | 发现职责膨胀 🎈 与指标副作用 ⚠️，配上平衡指标 ⚖️ |

## 🚀 使用

把岗位相关材料 🗞️（JD、访谈记录、业务需求描述）丢给 agent，说一句「帮我分析这个岗位」🗣️ 就行。skill 会默认按以下结构输出：

1. 📄 分析范围与证据 —— 材料从哪来、哪些是事实 🔎、还缺什么 🕳️
2. 🎯 岗位使命 —— 一句话使命 ✍️，加上边界与汇报/协作关系 🤝
3. 🪜 五步分析表 —— 步骤、结论、证据或待确认项 📋
4. 🧩 关键职责 —— 职责领域、具体动作 🏃、预期结果 🏁、频次/依赖 🔁
5. 🧠 任职能力 —— 类别、要求、可观察证据 👀、优先级 🔢
6. 📏 绩效指标建议 —— 名称、口径、周期、数据源、目标状态 🎯、平衡指标 ⚖️
7. 🖼️ 岗位画像与判断标准 —— 适配画像 🧍 与招聘/定岗决策要点 🧭
8. ⚠️ 风险与待确认问题 —— 信息不足 🕳️、边界冲突 ⚔️、指标副作用 🎭 和下一步 👣

> 💡 只提供岗位名称也行～ skill 会先给出基于常见岗位的暂定分析 📝，并明确标注 📌 哪些内容需要结合公司阶段 🌱、组织结构 🏢 和业务目标 🎯 校准，绝不假装掌握具体公司信息 🙊。
